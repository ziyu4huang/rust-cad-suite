讓 XLS 與 rverilator 共用同一個核心

不是把 XLS 的驗證外包給我們，而是讓 XLS 的模擬器插槽、我們的 CLI、瀏覽器面板與語料閘， 全部落在同一份 Rust 核心與同一組 oracle 期望值上。這頁說明為什麼可行、三階段怎麼做， 以及 S1 已經落地並在真 app 裡驗過的部分。

01為什麼可行：XLS 的模擬器本來就是插槽

先把「XLS 需要 Verilator」這個直覺拆掉——上游文件與原始碼都不支持它。

查證點上游事實（google/xls @ main）對我們的含義
verilog_simulator.h 純虛介面：Run(text, file_type, macros, includes) -> (stdout, stderr)，另有 RunSyntaxChecking。 「文字進、stdout/stderr 出」+ -D + -I = 我們的 CLI 已經具備的面。
simulators/ 只有 iverilog_simulator.cc：寫暫存 top.v → iverilog -o → vvp → 收輸出。 沒有 verilator_simulator.cc；插槽是空的，先到先贏。
Verilator 出現處 文件舉例、module_builder.cc 一行「Verilator 不喜歡陣列宣告與賦值同行」的註解。 是「範例」與「lint 遷就」，不是依賴。
已收編語料 corpus-external/xls：DSLX、IR、codegen Verilog（Apache-2.0）；corpus/e2e/57_xls_add3、58_xls_acc_pipe：race-safe TB + Verilator 錄製期望。 「XLS 產物 → 我們的閘」這條路已經通了，缺的是把它變成可視、可重用、可被 XLS 呼叫。
結論：XLS 不需要 Verilator，也不需要我們「取代」誰；它需要的是一個符合 VerilogSimulator 形狀的實作。我們要做的，是把同一個 Rust 核心接到那個插槽上， 並讓同一份核心同時服務 CLI、瀏覽器與 DSH 面板。

04介面契約對位

S2 把「剛好能跑」變成「形狀也對」：錯誤、巨集、include、exit code 都有明確歸屬，且每一格都有測試釘住。

XLS VerilogSimulator我們的等價物現況釘住的方式（contract test）
Run(text, ".v", macros, includes) rverilator --binary / WasmSim / rv-xls-sim CLI ✅、wasm ✅、adapter ✅ add3 / acc_pipe 的 stdout 與 oracle 期望 byte-equal（文字與 argv 兩條入口）；stdout 不得含 scratch 路徑。
RunSyntaxChecking(text, ...) --syntax-check ✅ 好設計：stdout / stderr 都空；壞設計：exit 1、stdout 空、stderr 含 diagnostics。
MacroDefinition -D NAME=VALUE ✅ `ifdef BIG 真的改變 stdout（big vs small），不是只被受理。
includes -I dir ✅ `include "defs.vh" 自 include 目錄解析，巨集值進 stdout（val=7）。
file_type = ".sv" V2005 範圍外 明確拒絕（milestone） exit 1，stderr 同時含 SystemVerilog 與 milestone；禁靜默降級。
SimulationResult{stdout, stderr} 兩個 stream ✅ 失敗：stdout 空、stderr 診斷；JSON 回應 round-trip（status/stdout/stderr/exit 型別正確）。

協定 v1（已實作）

兩種呼叫形狀共用同一個請求模型與同一個核心：argv 給 shell／上游子程序，JSON 給 in-memory 文字（XLS 的 Run 就是這個形狀）。

# argv 形：stdout = 設計輸出，stderr = 診斷，exit code 表成敗
rv-xls-sim --file top.v -D WIDTH=8 -I ./inc
rv-xls-sim --file top.v --syntax-check

# JSON 形：stdin → stdout（未知鍵忽略，向前相容）
{ "text": "module tb; initial begin $display(\"q=%0d\", 8); $finish; end endmodule",
  "file_type": ".v",
  "defines": { "WIDTH": "8" },
  "includes": ["./inc"],
  "syntax_only": false }
→ { "status": "ok", "stdout": "q=8\n", "stderr": "", "exit": 0 }

刻意不引入 serde：請求／回應是固定鍵的 JSON 子集，手寫遞迴下降解析器 + 單元測試 （跳脫、BMP／代理對、惡意輸入）就夠；錯誤一律 status: "error" + 非空 stderr， 不靠例外。完整契約（含分歧與非目標）見 docs/XLS-ADAPTER.md。

07風險與分歧（先登記，再前進）

項目風險處置
.sv 檔案型別 XLS 某些 codegen 需要 SystemVerilog；我們是 V2005 範圍。 明確硬錯 + milestone 標記；不在適配器裡靜默改寫。
timescale 正規化 XLS 沒有 timescale 概念，直接餵檔會觸發 TIMESCALEMOD（REGISTRY D16）。 維持「收割管線內注入」的語料政策；引擎行為不因個案改變。
stderr 措辭 XLS 測試若斷言 iverilog 的錯誤文字，換引擎就會紅。 契約只保證「非空且含失敗原因」；逐字差異登記，不假裝等價。
$finish／exit code iverilog 面與 rverilator 面的結束語義不同。 適配器固定映射：正常結束 0、編譯/執行錯誤 1；$finish 橫幅留在 stdout。
瀏覽器 ≠ 上游 面板綠了不代表 XLS 的 C++ 呼叫端可用。 L1 與 L2 分開驗收；S3 以上游測試實跑為準。
XLS 樹內驗證 本機沒有 Bazel；XLS release 只提供 linux-x64，macOS arm64 不能直接執行。解法已落地=CI 當 linux oracle（workflow_dispatch 自助觸發、artifact 自帶授權、adopt 腳本本機驗收），樹內閘=in-tree job。 子類對真 header 編譯＋harness 實跑；in-tree bazel test 明標 TODO，不假裝已驗。
