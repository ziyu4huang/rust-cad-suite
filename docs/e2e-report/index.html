Why this number is trustworthy

  1. Expectations are recorded, never authored. Every expected.stdout is captured by running the real Verilator (vl-difftest --record) and committed. Seven hand-authored expectations were proven wrong by the oracle earlier in this repo — recorded expectations are the policy since (AGENTS §1).
  2. Same pipeline as the product. Each case runs through the exact preprocess → parse → elaborate → schedule path the rverilator --binary CLI uses (vl_difftest::run_ours), then is compared byte-for-byte with the oracle stdout after one normalization: Verilator's own report block (lines starting - ) is dropped. No fuzzy matching anywhere.
  3. The corpus is semantics-clean by policy (AGENTS §2): no X/Z propagation samples (the oracle is a 2-state evaluator — 4-state correctness is gated separately by IEEE §5 truth-table unit tests in vl-sim), and no same-edge scheduling races (IEEE-nondeterministic constructs were rewritten mid-cycle; see corpus/e2e/26, 43 for the documented pattern).
  4. The gate is mechanical. The ≥80% assertion lives in crates/vl-difftest/tests/regression_gate.rs, runs in every cargo test, and fails the build when the rate drops — including on machines without Verilator installed.
  5. The one non-pass is declared scope. 30_gen_mux uses memory arrays; the simulator hard-errors with (milestone M7) by design (AGENTS §3 — silent misexecution is the banned failure mode).
