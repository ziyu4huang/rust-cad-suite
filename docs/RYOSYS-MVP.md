## 1. 定位与 M0(MVP)边界

### 1.1 定位

ryosys = yosys 的纯 Rust 等价物。MVP 不是「迷你玩具」而是一条**完整纵切**:
RTLIL 文本进 → IR 全环(读/检查/统计/双后端出),oracle 逐 byte 对拍。策略
枢纽 = **RTLIL-first**:yosys 的 IR 文本形态(read_rtlil)既是它的稳定前端
接口,又是绕开 17.6k 行 Verilog/ast 前端的侧门——golden 生成期借 oracle 的
read_verilog+proc 把外部语料「预处理」成 process-free .il,ryosys 本体从
RTLIL 起步。Verilog 前端、proc/优化等综合能力按里程碑弧后置(对齐
RIVERILOG「先 CLI 契约定桩再逐弧长能力」的 R0 先例)。

### 1.2 M0 做(纵切清单)

- `ryosys` 二进制:`-p "<script>"` 单一脚本入口(oracle 同形)+ `-V`
  自标识(不冒充 yosys 版本串,登记分歧 D-ys1)。
- 命令 registry=**两层**(「仅 5」的说法废弃:read_verilog 等已知名命令
  必须在登记层占名,否则会误报「No such command」的**错误错误面**):
  **实现层** 5 命令——`read_rtlil` / `write_rtlil`(仅 `-readable` 形)/
  `write_json` / `check` / `stat`(仅无参子集);**登记层**=录制轮
  `yosys -H` 命令普查(§0-12 实测 306 条)逐字入 PROVENANCE,命中→
  `ERROR: <cmd>: not implemented in ryosys (milestone Yx)`,Y 码映射:
  **hierarchy/simplemap/read_json(排期 M1)→Y0(M1 移除 stub);proc/opt
  家族→Y2;read_verilog/read_sverilog 前端族→Y3;其余→Y0**。
  **普查外**名字才逐字重现 oracle 的
  `ERROR: No such command: %s (type 'help' for a command overview)`(§0-3
  实测)。
- `-p` 解析契约=**token 尾分号切分**(§0-11 实测;源码=kernel/register.cc
  的 `Pass::call` 词法循环——调研早前「driver.cc run_pass」指针有误,已正):
  空白(` \t\r\n`)定界 token,**仅尾字元为 `;` 时切分**——`clean;clean`
  (无空白)=单一未知命令 exit 1,`clean; clean`(带空白)=两命令;
  尾 `;;`→该命令后追加 `clean`、`;;;`→`clean -purge`;`#` 开头 token=
  注释;引号内 `;` 不切;换行亦命令边界。**无空格暗角形必入 fixture 组**,
  先钉死再扩命令面。
- `ry-ir`:RTLIL **全实体语法**解析(**design 级顶层形态**:attribute 行+
  module/end+autoidx 计数行——§0-10 实测 87 檔 col-0 行仅此四种,autoidx
  87/87 必现且 roundtrip **回放值逐字保留**;module 内部 wire/cell/
  connect/memory/process+case/sync/memwr 区块一次到位——按构造切子集会
  立刻破坏 roundtrip 闸;**「一次到位」的 M0 验收面=§4.1 P-bearing 层
  roundtrip golden(实测 54 例含 process/case/sync、3 例含 memwr——
  memwr 覆盖不足处由 M2 proc 弧补)**)+常数模型(位宽/x/z/补位规则:
  `1` 补 `0`、`x`
  补 `x`、全-x 短写 `4'x`;32-bit 全定值 autoint 十进制形态)+**插入序
  容器**(oracle dict 迭代语义:dump 走 reversed=插入序,rtlil_backend.cc:
  37/177)+ID 词法逐字照抄(反引号或 `$` 开头吃到空白、名字可含 `[]:`、
  切片前必须有空格;**`$paramod\submod\c=s3'111\d=s3'111` 这类内嵌
  sized 常数与反斜线名的复合类型是单 token**,词法 fixture 必含)。
- `check` 子集:known-cell 期望参数/端口表(kernel/rtlil.cc:1600+)的移植
  边界**量化钉死**=语料普查的 **46 种简式 `$` 内建 cell**(§0-10;清单入
  PROVENANCE,录制轮遇新类型=扩表同轮修 check);16 个 `$paramod…` 复合名
  与 13 个 public `\mod` 实例类型**不走内部期望表**(check 对它们不做
  known-cell 参数校验,覆盖面=ID 词法/连线 roundtrip)。命令集极小(5 命令)
  ≠check 表极小——M0 闸②的 check 输出逐字对拍隐含全部 46 种表项,此为
  已量化承诺而非「按语料子集」的开放表述;`stat` 无参子集(sort_by_id_str
  排序+固定缩排+`=== top ===` 标头,oracle golden)。
- 差分闸:`corpus/ys-e2e/` committed goldens + `ry-difftest`(§4)。

## 2. crate 布局与命名(对齐本仓惯例,写入 crates/)

```
crates/
├── ry-ir/         RTLIL 对象模型 + lexer/parser + 打印机(-readable 形)
│                  [0 外部依赖;插入序 map 自带]
├── ry-cli/        bin `ryosys`(registry + -p 解析 + check/stat/write_*)
│                  [ry-ir;0 外部依赖——手写 flags,同 vl-cli 惯例]
└── ry-difftest/   dev-only oracle 差分 harness(录制/对拍/归一化)
                   [publish=false,同 vl-difftest/riv-difftest 惯例]
corpus/ys-e2e/     案例目录:<case>/{case.il, expected.rtlil, expected.json,
                  expected.stdout, expected.stderr, expected.exit}(入 git);
                  根级 corpus/ys-e2e/PROVENANCE(oracle 版本串/录制日期/
                  排除表/46 种内建 cell 普查表)——PROVENANCE 是 corpus 级
                  单檔,不放案例目录
```

命名理由:产品线前缀家族(vl-/riv- → ry-);bin 名 `ryosys` **不冒名
`yosys`**(PATH 安全,免毒化自家 oracle——PLAN §8 #2 暂定裁决同款理由);
difftest 命名对齐 vl-difftest/riv-difftest。核心 crate 零外部依赖
(PLAN §2 政策);将来若需 JSON 解析(M1 read_json)在 ry-ir 内手写
最小 parser,不引 serde(与 FFI 行式 manifest 同哲学)。

## 4. oracle 对拍设计

### 4.1 corpus 策略(golden 录制入 git;测试运行零 oracle)
